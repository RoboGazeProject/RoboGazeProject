02Method

Ground the task, route to specialists, verify.

One frozen VLM plays every role, with no task-specific training. It grounds the instruction and the scene, sends each subtask only to the failure specialists that matter, and lets a critic accept, merge or reject every candidate before it enters the report.

05Scope
Visible failures only

An empty report means no failure is visible in the sampled frames. It does not show that the behavior is executable on a robot.

One camera view

Benchmark clips are single-view; consistency across cameras is not evaluated.

Several VLM calls per clip

The paper compares RoboGaze with controls given an equal or larger inference budget.

06Use & extend

Three ways to use RoboGaze.

Diagnose your own generated videos, benchmark another evaluator on RoboGazeBench, or extend the framework with a new backbone, failure type or data. None of them requires training.

A

Diagnose your videos

1Inputs

“Press the pink, then the blue, then the green button.”

A generated video, its first frame and the task instruction.

2Run RoboGaze on a frozen VLM

Ground→Route→Verify

One frozen VLM plays every role. No fine-tuning.

3Read the report

Object disappearance12.0–19.0 sObject–Scene ConsistencySeverity 4 / 5

One report per clip. A clean clip gets an empty list.

B

Benchmark your evaluator

1Load the data

914 clips, 1,847 failures, 210 clean clips.

2Run yours

Export one event list per clip: dimension, type, start and end time, severity, description.

3Match events

Events are matched to the human reference by time overlap and description.

4Compare

Description F1, temporal IoU and clean-clip accuracy, next to CoT (23.5), GLiDE+ (46.0) and RoboGaze (57.3).

C

Extend the framework

New backbone

Wrap any VLM behind one call: frames and a prompt in, text out.

New failure type

Add its definition and a specialist prompt. Scoring needs new annotations.

New data

Add clips from a new generator or robot with reference annotations, then score them as in B.

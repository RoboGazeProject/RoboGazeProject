Use RoboGaze on your videos

RoboGaze diagnoses visible failures in generated robot-manipulation videos using frozen vision-language models. You do not fine-tune the evaluator to inspect a new video.

1. Prepare a clip and its task

Keep the original generated video, the instruction used to condition it, and the initial scene observation together. Scene context helps distinguish a genuine change from an object that was present from the start. Preserve the original duration and timestamp scale when sampling frames.

The input file for the glass-and-dispenser clip lists the generated video, its instruction and the initial scene frame; paths are relative to the JSON file. Open this clip in the interactive viewer.

{
  "clip_id": "cp_ic_dispenser",
  "video": "../videos/clips/cp_ic_dispenser.mp4",
  "instruction": "Use the right hand to pick up the glass, place it under the Coca-Cola dispenser, and press the lever to fill it",
  "initial_observation": "../images/usage/dispenser-initial.jpg",
  "duration_s": 5.81,
  "fps": 16,
  "resolution": "1280x800"
}

2. Configure a VLM and run diagnosis

Use a VLM interface that can process the sampled video frames and return structured text. An API-backed model or a locally served model can fill this role. The task parser, observer, router, specialists, and critic use prompts to the same frozen backbone.

The paper's default observer uses non-overlapping 4-second windows, 16 frames per window, up to three routed dimensions per subtask, and a critic confidence threshold of 0.50. These describe the reported method, not configuration keys guaranteed by a particular implementation. Keep the model's visual-input policy fixed when comparing methods, and record the model identifier, prompts, sampling settings, and configuration with each run.

The workflow is: ground the task and scene; inspect temporal windows; route relevant segments to dimension specialists; verify and consolidate candidate events.

3. Read the report

RoboGaze's report for the glass-and-dispenser clip contains five events. Each event identifies a dimension and type, a start and end time in seconds, severity, and a description of the visible evidence. evidence_limiting marks types that record that the frames cannot decide, rather than asserting a defect. Severity runs from 1 (cosmetic) to 5 (invalidates the depicted execution).

Use timestamps to return to the video and inspect the evidence. Distinguish a supported defect from an event whose type records that the evidence cannot decide. An empty event list means no visible failure was supported by the inspected frames; it does not establish physical executability.

For comparison, the input of a failure-free mug-placement clip receives a report with an empty event list. Open the clean clip alongside the failure case.

4. Scale to a collection

Apply the same input preparation and configuration to each generated clip. Retain per-clip reports and summarize event dimensions, types, and severities to guide inspection. Human reference labels are not required for this diagnostic use. They are required to measure the evaluator's detection accuracy using the benchmark protocol.

The website gallery shows saved RoboGaze reports. Selecting a clip or clicking an event replays the saved report; it does not run inference.

Extend RoboGaze

The following integration paths describe how to adapt the framework. They are architectural guidance, not a claim that a plugin API or automatic registration command is already available.

Add a VLM backend

Adapt the backend's multimodal request/response interface, including image/video sampling, frame limits, structured-output parsing, and error handling. Keep the task grounding, routing, specialist, and verification roles consistent. Check short and long clips, failure-free clips, malformed outputs, and timestamp preservation before comparing benchmark results. A model must support the required visual inputs; training-free does not guarantee compatibility with every model.

Add a dataset or generator

Prepare generated video, task instruction, and scene context for each clip. Preserve duration, timestamps, generator provenance, and embodiment metadata. The evaluator can diagnose these clips without retraining. If the goal is to measure its accuracy, annotate reference events with the shared schema, include failure-free clips, and apply the benchmark protocol. Keep prompt/threshold development conditions separate from evaluation conditions.

Adapt the failure schema

Define the new dimension/type, its boundaries, normal alternatives, and severity rubric. Update routing and specialist prompts as needed, then check critic decisions and output validation. Review annotation consistency and scoring before comparing against an existing benchmark. A changed schema requires a versioned evaluation; its numbers are not automatically comparable to the original six-dimension, thirty-type schema.

Check an extension

Use a small collection containing a clear failure, a clean clip, a brief event, an occlusion/uncertainty case, and a long clip. Inspect the evidence, temporal boundaries, duplication/merging, and empty-report behavior. Follow with the full shared evaluation when reporting quantitative improvements. Record the backend, schema, prompts, configuration, and data version.
